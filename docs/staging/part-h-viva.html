Πληρωμές Viva (demo)

Ο διοργανωτής συνδέει τον δικό του λογαριασμό Viva — εδώ, τον δοκιμαστικό. Πρώτα μια κράτηση χωρίς Viva, για να ξέρετε ότι τα υπόλοιπα δουλεύουν. Μετά η Viva.

Πρώτα χωρίς Viva

Με κλειδί pk_test_ και χωρίς δοκιμαστικά διαπιστευτήρια Viva, το Kaiki στέλνει την πληρωμή στη δική του ψεύτικη σελίδα /sandbox/checkout/…, με δύο κουμπιά: επιτυχία και αποτυχία. Κάντε μία κράτηση έτσι από το aegeancr.gr. Αν έρθει το email επιβεβαίωσης με το εισιτήριο, λειτουργούν ουρά, email, Chromium και σελίδα κράτησης· ό,τι σπάσει μετά τη σύνδεση της Viva, είναι της Viva.

Ο λογαριασμός demo της Viva

  1. Λογαριασμός στο https://demo.vivapayments.com — ξεχωριστός από τον κανονικό, με δικά του κλειδιά. Τα demo και live είναι διαφορετικοί servers της Viva (demo-accounts, demo-api, demo).
  2. Settings → API Access: σημειώστε Merchant ID και API Key, και δημιουργήστε Smart Checkout credentials για Client ID και Client Secret.
  3. Νέα πηγή πληρωμών (payment source) για ιστότοπο, με domain kaiki.testing.gr. Σημειώστε τον τετραψήφιο κωδικό πηγής (source code). Τα Success URL και Failure URL τα παίρνετε από το Kaiki στο επόμενο βήμα.
Ονόματα μενού της Viva

Τα ονόματα των οθονών της Viva δεν βγαίνουν από τον κώδικα του Kaiki και αλλάζουν με τις εκδόσεις του dashboard της. Ο κώδικας επιβεβαιώνει μόνο ότι χρειάζονται αυτά τα πέντε στοιχεία, και ότι Merchant ID και API Key είναι στην ίδια σελίδα με τα Smart Checkout credentials (app/Enums/IntegrationProvider.php).

Στο Kaiki: Συνδέσεις

  1. https://kaiki.testing.gr/app, ως ιδιοκτήτης (η οθόνη δεν φαίνεται σε διαχειριστή ή πλήρωμα): Ρυθμίσεις → Συνδέσεις → Νέα σύνδεση.
  2. Πάροχος Viva Wallet, Περιβάλλον Δοκιμαστικό, «Χρήση στο ταμείο» ενεργό. Πεδία: Αναγνωριστικό πελάτη (Client ID), Μυστικό πελάτη (Client secret), Αναγνωριστικό εμπόρου (Merchant ID), Κλειδί API, Κωδικός πηγής πληρωμής. Αποθήκευση. Τα μυστικά δεν ξαναεμφανίζονται — μόνο τα τέσσερα τελευταία ψηφία.
  3. Στην κάρτα της σύνδεσης εμφανίζεται «Η δική σας διεύθυνση webhook», της μορφής https://kaiki.testing.gr/webhooks/viva/ΜΟΝΑΔΙΚΟ-TOKEN, με κουμπί Αντιγραφή. Πιο κάτω, στο «Viva: πού επιστρέφει ο πελάτης μετά την πληρωμή», οι δύο διευθύνσεις: https://kaiki.testing.gr/pay/viva/success και …/pay/viva/failure.

Πίσω στη Viva

  1. Στην πηγή πληρωμών: Success URL και Failure URL από το Kaiki.
  2. Στα Webhooks του λογαριασμού: νέο webhook με τη διεύθυνση του Kaiki, γεγονός Transaction Payment Created. Η Viva καλεί τη διεύθυνση με GET για επιβεβαίωση· το Kaiki απαντά μόνο του, διαβάζοντας το κλειδί επιβεβαίωσης από τη Viva με Merchant ID και API Key. Δεν αντιγράφετε κανένα κλειδί με το χέρι.
Αν η Viva λέει ότι η διεύθυνση δεν επιβεβαιώθηκε

Σχεδόν πάντα φταίει ο server, όχι το Kaiki: ο Basic Auth καλύπτει το /webhooks/, ένα WAF μπλοκάρει την κλήση, υπάρχει AAAA εγγραφή χωρίς IPv6, ή το πιστοποιητικό δεν είναι έγκυρο. Δοκιμάστε από οποιονδήποτε υπολογιστή: curl -i https://kaiki.testing.gr/webhooks/viva/TOKEN — πρέπει να δώσει 200 με JSON {"Key": …}. Το 401 ή μια σελίδα του πίνακα είναι ο server. Το {"received":false} με 502 σημαίνει λάθος Merchant ID ή API Key (ή λάθος περιβάλλον)· με 404, λάθος διεύθυνση.

Ο διοργανωτής ως «δοκιμαστικός λογαριασμός»

Από το WordPress, το αν μια κράτηση είναι δοκιμαστική το αποφασίζει το κλειδί (pk_test_). Από τις σελίδες book.kaiki.testing.gr δεν υπάρχει κλειδί του διοργανωτή· εκεί το αποφασίζει ο διακόπτης «Δοκιμαστικός λογαριασμός» στο /admin → Έμποροι → Επεξεργασία. Ανοίξτε τον για κάθε διοργανωτή του staging. Οι κρατήσεις του μαρκάρονται δοκιμαστικές και δεν μπαίνουν σε καμία αναφορά. Χωρίς αυτόν, μια κράτηση από σελίδα book. ζητά ζωντανά διαπιστευτήρια Viva — που στο staging δεν πρέπει να υπάρχουν.

Μια κράτηση από την αρχή ως το τέλος

  1. Στο aegeancr.gr, σελίδα εκδρομής: ημερομηνία, άτομα, στοιχεία, «Κράτηση».
  2. Η σελίδα ολοκλήρωσης kaiki.testing.gr/c/…: σύνοψη, όροι, «Πληρωμή».
  3. Η σελίδα της Viva (demo.vivapayments.com): μία από τις κάρτες δοκιμής που δημοσιεύει η Viva στην τεκμηρίωση για developers (developer.viva.com, «Test cards»), με οποιαδήποτε μελλοντική λήξη. Αν ζητήσει 3-D Secure, ολοκληρώστε το.
  4. Επιστροφή στο /pay/viva/success → σελίδα κράτησης /b/…. Μπορεί για λίγα δευτερόλεπτα να γράφει ότι η πληρωμή επεξεργάζεται: την επιβεβαίωση τη φέρνει το webhook.
  5. Email επιβεβαίωσης στον πελάτη με το εισιτήριο PDF (από τον worker). Στο πάνελ: η κράτηση επιβεβαιωμένη, η πληρωμή πληρωμένη, το μήνυμα στο Μηνύματα.
  6. «← Επιστροφή στην ιστοσελίδα» → πίσω στο aegeancr.gr.
  7. Στο dashboard της Viva demo: η συναλλαγή, και στα webhooks μια επιτυχημένη αποστολή.
Αν το webhook δεν έρθει ποτέ

Το payments:reconcile (cron, κάθε πέντε λεπτά) ρωτά τη Viva για κάθε πληρωμή που περιμένει πάνω από πέντε λεπτά και επιβεβαιώνει όσες πληρώθηκαν. Άρα μια κράτηση που επιβεβαιώνεται μετά από 5–10 λεπτά και όχι αμέσως σημαίνει: η πληρωμή δουλεύει, το webhook όχι. Ό,τι απέτυχε φαίνεται στο Τι πήγε στραβά του πάνελ.
