Μέρος Γ

Εγκατάσταση

Μία φορά, με αυτή τη σειρά. Χωρίς Docker και χωρίς Caddy: δεν υπάρχουν ακόμη στο αποθετήριο (M8, #13 και #14), οπότε το Kaiki στήνεται απευθείας πίσω από τον web server του πίνακα.

Πριν ξεκινήσετε

Σε όλο τον οδηγό, τα παραδείγματα χρησιμοποιούν:

Χρήστης του sitekaikistg
Φάκελος της εφαρμογής/home/kaikistg/kaiki
PHP στη γραμμή εντολώνphp8.4 — βάλτε τη διαδρομή που σας έδωσε η Cretaforce
Αποθετήριοgithub.com/mikmikfil/kaiki (ιδιωτικό), κλάδος main

Αντικαταστήστε τα με τα δικά σας. Η σειρά των βημάτων δεν αλλάζει.

Στον πίνακα της Cretaforce

  1. Νέο subdomain kaiki.testing.gr και, στο ίδιο site, δεύτερο όνομα (alias) book.kaiki.testing.gr. Αν ο πίνακας δεν δέχεται alias, δεύτερο subdomain με τον ίδιο document root.
  2. Document root: /home/kaikistg/kaiki/public. Ποτέ ο φάκελος πάνω από το public/ — εκεί είναι το .env με τους κωδικούς. Αν ο πίνακας επιμένει σε δικό του φάκελο (π.χ. public_html), ζητήστε από την υποστήριξη να τον αλλάξει, ή κάντε τον symlink προς το kaiki/public.
  3. Επιλογή PHP: 8.4, σε FPM.
  4. SSL Let's Encrypt και για τα δύο ονόματα, αφού έχουν μπει τα A records (μέρος Β). Ενεργοποιήστε την ανακατεύθυνση από HTTP σε HTTPS.
  5. Νέα βάση MySQL: kaiki_staging, χρήστης kaiki_staging, δυνατός κωδικός, collation utf8mb4_unicode_ci.

Στον server, με SSH

1. Κλειδί για το GitHub και clone

Το αποθετήριο είναι ιδιωτικό. Φτιάξτε ένα κλειδί μόνο για αυτόν τον server και δώστε το στο GitHub ως Deploy key μόνο για ανάγνωση (Settings → Deploy keys → Add deploy key). 

ssh-keygen -t ed25519 -C "kaiki-staging" -f ~/.ssh/kaiki_deploy -N ""
cat ~/.ssh/kaiki_deploy.pub        # αυτό επικολλάτε στο GitHub

cat >> ~/.ssh/config <<'EOF'
Host github-kaiki
  HostName github.com
  User git
  IdentityFile ~/.ssh/kaiki_deploy
EOF

cd /home/kaikistg
git clone git@github-kaiki:mikmikfil/kaiki.git kaiki
cd kaiki

2. Το .env

cp .env.example .env
nano .env                          # ολόκληρο το περιεχόμενο είναι στο μέρος Δ
chmod 600 .env

3. Εξαρτήσεις PHP και κλειδί εφαρμογής

php8.4 $(command -v composer) install --no-dev --optimize-autoloader
php8.4 artisan key:generate

Αν το Composer λέει «Your Composer dependencies require a PHP version >= 8.4.1», το php της γραμμής εντολών είναι παλιότερο — γι' αυτό η εντολή καλεί ρητά το php8.4. Το key:generate γράφει το APP_KEY στο .env· μην το αλλάξετε μετά, γιατί με αυτό είναι κρυπτογραφημένα τα κλειδιά της Viva.

4. Build: η εφαρμογή και το widget

export PUPPETEER_SKIP_DOWNLOAD=1   # χρησιμοποιούμε το Chromium του server
npm ci                             # όχι --omit=dev: το puppeteer χρειάζεται για τα PDF
npm run build                      # Vite → public/build
npm run widget:build               # → packages/widget/dist/kaiki-widget.js
php8.4 artisan widget:publish      # → public/widget/vX.Y.Z/ και το alias
Το widget:publish δεν είναι προαιρετικό

Ο φάκελος public/widget δεν είναι στο git. Το widget:build φτιάχνει το αρχείο μέσα στο packages/widget/dist· μόνο το widget:publish το αντιγράφει εκεί που το ζητά το WordPress (/widget/kaiki-widget.js) και γράφει το /widget/manifest.json. Χωρίς αυτό η φόρμα κράτησης δεν φορτώνει πουθενά.

5. Αποθήκευση αρχείων, βάση

php8.4 artisan storage:link        # public/storage → φωτογραφίες εκδρομών, σκαφών, λιμανιών
php8.4 artisan migrate --force

Οι φωτογραφίες του καταλόγου πάνε στον δίσκο public (storage/app/public) και δίνονται στο WordPress ως κανονικές διευθύνσεις. Εισιτήρια, λογότυπα, εξαγωγές και έγγραφα πελατών πάνε στο storage/app/private, που δεν σερβίρεται ποτέ απευθείας.

6. Δεδομένα: demo ή καθαρό

Με δεδομένα επίδειξης

Το DatabaseSeeder φτιάχνει τρεις διοργανωτές (aegean-blue, ionian-sunset, actionseaze) με σκάφη, εκδρομές, αναχωρήσεις, φωτογραφίες, συχνές ερωτήσεις, αρχική σελίδα και μια σεζόν κρατήσεων. Οι κρατήσεις φτιάχνονται από τις πραγματικές ενέργειες, άρα μπορεί να μπουν στην ουρά email και PDF προς τις ψεύτικες διευθύνσεις @example.com. Γι' αυτό: seed με MAIL_MAILER=log, άδειασμα της ουράς, και μετά αληθινό SMTP. 

# στο .env, προσωρινά: MAIL_MAILER=log
php8.4 artisan config:clear
php8.4 artisan db:seed --force
php8.4 artisan queue:work --stop-when-empty   # τα email πάνε στο log, τα PDF φτιάχνονται
# μετά: MAIL_MAILER=smtp στο .env
Πλατφόρμα (/admin)admin@kaiki.example
Aegean Blue (/app)maria@aegean-blue.example (ιδιοκτήτρια), giorgos@… (διαχειριστής), nikos@… (πλήρωμα)
Ionian Sunsetelena@ionian-sunset.example, andreas@…
Actionseazedimitris@actionseaze.example
Κωδικός όλωνpassword
Αλλάξτε τους κωδικούς αμέσως

Ο server είναι δημόσιος και οι λογαριασμοί είναι γραμμένοι στον κώδικα. Αλλάξτε τουλάχιστον του admin@kaiki.example και της maria@…: 

php8.4 artisan tinker --execute="App\Models\User::where('email','admin@kaiki.example')->update(['password'=>Hash::make('ΝΕΟΣ-ΚΩΔΙΚΟΣ')]);"

Οι διευθύνσεις .example δεν λαμβάνουν email, άρα «ξέχασα τον κωδικό» δεν δουλεύει γι' αυτούς. Ο κωδικός Basic Auth του μέρους Ε είναι το δεύτερο κλείδωμα.

Καθαρό, χωρίς demo

Δεν υπάρχει εντολή για διαχειριστή πλατφόρμας· τον φτιάχνετε μία φορά με το tinker:

php8.4 artisan tinker --execute="App\Models\User::forceCreate(['name'=>'Mike','email'=>'ΕΣΕΙΣ@ΤΟ-DOMAIN','password'=>Hash::make('ΚΩΔΙΚΟΣ'),'email_verified_at'=>now(),'locale'=>'el','tenant_id'=>null,'is_super_admin'=>true]);"

Μετά, στο /admin → Έμποροι → νέος διοργανωτής. Ο ιδιοκτήτης παίρνει πρόσκληση με email. Αν το email δεν έχει στηθεί ακόμη, το php8.4 artisan kaiki:invitation-link ΔΙΕΥΘΥΝΣΗ τυπώνει τον σύνδεσμο ορισμού κωδικού — αρνείται μόνο όταν APP_ENV=production.

7. Caches και δικαιώματα

php8.4 artisan config:cache
php8.4 artisan route:cache
php8.4 artisan view:cache

chmod -R ug+rwX storage bootstrap/cache

Και τα τρία caches δοκιμάστηκαν στον κώδικα αυτής της έκδοσης και περνούν. Προσοχή: τα KAIKI_HOSTED_HOST και οι διαδρομές «ψήνονται» στο route cache. Κάθε αλλαγή στο .env θέλει ξανά config:cache και route:cache.

Ο PHP-FPM του site, ο worker και το cron πρέπει να τρέχουν ως ο ίδιος χρήστης (kaikistg), αλλιώς ο ένας γράφει αρχεία στο storage/ που ο άλλος δεν μπορεί να ανοίξει.
