Μέρος Β

Ο server

Τι πρέπει να υπάρχει στον dedicated server πριν ξεκινήσετε, τι ζητάτε από την Cretaforce, και ποιες εγγραφές DNS φτιάχνετε.

Ό,τι χρειάζεται

Κάθε γραμμή βγαίνει από τον κώδικα: composer.json, package.json, τα config/*.php και το CI (.github/workflows/ci.yml). Σημειώστε δίπλα τι έχει ήδη ο server· ό,τι λείπει μπαίνει στο email της επόμενης σελίδας.

PHP 8.4 (FPM και CLI) 8.4.1 ή νεότερη — το vendor/composer/platform_check.php σταματά οτιδήποτε παλιότερο. Η ίδια έκδοση στο FPM του subdomain και στη γραμμή εντολών (SSH, cron, worker).
Επεκτάσεις PHP intl (απαιτείται ρητά), pdo_mysql, redis (phpredis — το predis δεν είναι εγκατεστημένο), gd (οι εικόνες επεξεργάζονται με GD), mbstring, curl, openssl, dom, xml, xmlreader, xmlwriter, fileinfo, zip, iconv, tokenizer, ctype, bcmath, opcache.
Ρυθμίσεις PHP Οι proc_open και proc_get_status να μην είναι στο disable_functions: τα PDF βγαίνουν με εξωτερική διεργασία (Browsershot → Node → Chromium), και το Composer τις χρειάζεται επίσης. memory_limit 256M ή παραπάνω, upload_max_filesize και post_max_size 20M (εισαγωγές από WordPress).
Composer 2 Στη γραμμή εντολών του χρήστη του site.
Node.js 22 και npm Η έκδοση του CI. Χρειάζεται και μετά το build: τα PDF φτιάχνονται από το Puppeteer μέσα στο node_modules της εφαρμογής, άρα το node πρέπει να τρέχει και για τον worker.
MySQL 8.0 Μια βάση utf8mb4 / utf8mb4_unicode_ci και ένας χρήστης μόνο γι' αυτήν. Το σχήμα ελέγχεται στο CI απέναντι σε MySQL 8.0· MariaDB δεν έχει δοκιμαστεί.
Redis 6 ή 7 Ουρά, cache και κλειδώματα (το onOneServer του scheduler). Μόνο στο 127.0.0.1. Αν το Redis το μοιράζονται κι άλλα sites, ξεχωριστός αριθμός βάσης και prefix (μέρος Δ).
Supervisor (ή systemd) Κρατά ζωντανό τον worker της ουράς. Horizon δεν είναι εγκατεστημένο — σκέτο queue:work.
Cron Μία γραμμή, κάθε λεπτό, ως χρήστης του site: php artisan schedule:run.
Chromium + γραμματοσειρές Headless Chromium ή Google Chrome, με τις βιβλιοθήκες του. Γραμματοσειρές με ελληνικά: τα πρότυπα PDF ζητούν DejaVu Sans και Helvetica/Arial (π.χ. στο Debian fonts-dejavu-core, fonts-liberation, fonts-noto-core). Χωρίς αυτές τα ελληνικά βγαίνουν κουτάκια.
SSH, git Κανονικό shell για τον χρήστη του site (όχι μόνο SFTP), και πρόσβαση προς το GitHub.
Εξερχόμενες συνδέσεις HTTPS προς demo-accounts.vivapayments.com, demo-api.vivapayments.com, demo.vivapayments.com, api.open-meteo.com, github.com, registry.npmjs.org, repo.packagist.org· SMTP προς τον mail server.
Οι θύρες 80 και 443 μένουν στον web server του πίνακα

Το Kaiki δεν ανοίγει δική του θύρα. Τρέχει ως PHP-FPM πίσω από τον web server που ήδη εξυπηρετεί τις άλλες ιστοσελίδες, σαν άλλο ένα site. Redis και MySQL ακούν μόνο τοπικά. Οι υπόλοιπες ιστοσελίδες δεν επηρεάζονται — εκτός αν μοιράζονται την ίδια βάση Redis χωρίς prefix, γι' αυτό το μέρος Δ δίνει δικό του αριθμό.

Το email προς την Cretaforce

Ο πίνακας της Cretaforce είναι δικός της, και δεν ξέρουμε ποιες από αυτές τις ρυθμίσεις έχει σε οθόνη. Ό,τι δεν βρίσκετε στον πίνακα, το ζητάτε. Αντιγράψτε, σβήστε ό,τι έχετε ήδη, και συμπληρώστε τα κεφαλαία.

Θέμα: Dedicated server ΟΝΟΜΑ — ρύθμιση για νέα εφαρμογή Laravel σε subdomain

Καλησπέρα σας,

στον dedicated server μας θέλουμε να στήσουμε μια εφαρμογή Laravel 12 στα subdomains kaiki.testing.gr και book.kaiki.testing.gr (ίδιος φάκελος, ίδια εφαρμογή), χωρίς να επηρεαστούν οι ιστοσελίδες που ήδη φιλοξενούνται. Θα θέλαμε να μας πείτε τι από τα παρακάτω υπάρχει και να ενεργοποιήσετε ό,τι λείπει:

  1. PHP 8.4 (8.4.1+) σε PHP-FPM για τα δύο subdomains, και η ίδια έκδοση στη γραμμή εντολών μέσω SSH (ποια είναι η διαδρομή, π.χ. /usr/bin/php8.4;).
  2. Επεκτάσεις: intl, pdo_mysql, redis (phpredis), gd, mbstring, curl, openssl, dom, xml, xmlreader, xmlwriter, fileinfo, zip, iconv, tokenizer, ctype, bcmath, opcache.
  3. Οι proc_open και proc_get_status να μην είναι απενεργοποιημένες. memory_limit 256M, upload_max_filesize και post_max_size 20M.
  4. Document root και των δύο subdomains: /ΔΙΑΔΡΟΜΗ/kaiki/public, και πιστοποιητικό Let's Encrypt και για τα δύο.
  5. SSH με κανονικό shell για τον χρήστη του site, με git, Composer 2 και Node.js 22 με npm.
  6. MySQL 8.0 (όχι MariaDB): μια βάση utf8mb4 και χρήστης.
  7. Redis στο 127.0.0.1 — υπάρχει ήδη; Αν το χρησιμοποιούν κι άλλα sites, ποιον αριθμό βάσης να πάρουμε;
  8. Supervisor (ή systemd service) για δύο διεργασίες php artisan queue:work ως χρήστης του site, με αυτόματη επανεκκίνηση. Σας στέλνουμε το ακριβές block.
  9. Cron κάθε λεπτό ως χρήστης του site: php artisan schedule:run.
  10. Headless Chromium ή Google Chrome με τις βιβλιοθήκες του, και γραμματοσειρές με ελληνικά (DejaVu, Liberation, Noto). Ποια είναι η διαδρομή του εκτελέσιμου;
  11. Ο web server περνά τα αιτήματα απευθείας στο PHP-FPM ή μέσω reverse proxy (π.χ. nginx μπροστά από Apache); Αν μέσω proxy, από ποια IP;
  12. Προστασία με κωδικό (Basic Auth) σε όλο το subdomain εκτός από συγκεκριμένες διαδρομές, και header X-Robots-Tag: noindex, nofollow. Επισυνάπτουμε το snippet.
  13. Αν υπάρχει ModSecurity/WAF: να μην μπλοκάρει POST με JSON προς /api/v1/ και /webhooks/, ούτε τις κλήσεις της Viva Wallet προς /webhooks/viva/.
  14. Εξερχόμενο HTTPS προς vivapayments.com, open-meteo.com, github.com, npmjs.org, packagist.org.
  15. Γραμματοκιβώτιο ή SMTP relay για αποστολή από noreply@kaiki.testing.gr, με DKIM — ποιες εγγραφές DNS να προσθέσουμε; Και reverse DNS (PTR) για την IP του server.

Ευχαριστούμε πολύ,
ΟΝΟΜΑ, ΤΗΛΕΦΩΝΟ

Το snippet για το 12 είναι στο μέρος Ε («Κωδικός και noindex»), σε δύο παραλλαγές: Apache και nginx. Το block του Supervisor για το 8 είναι επίσης στο μέρος Ε.

Εγγραφές DNS στην Cretaforce

Το DNS είναι στην Cretaforce, άρα οι εγγραφές μπαίνουν στον ίδιο πίνακα. Φτιάξτε τις πριν ζητήσετε πιστοποιητικό: το Let's Encrypt ελέγχει ότι το όνομα δείχνει στον server.

Όνομα · τύποςΤιμή
kaiki.testing.gr · Aη IPv4 του server
book.kaiki.testing.gr · A η ίδια IPv4 (ή CNAME προς kaiki.testing.gr)
AAAA (και για τα δύο) Μόνο αν ο server εξυπηρετεί το subdomain και σε IPv6. Αλλιώς καμία — ένα AAAA που δεν απαντά κάνει τη Viva και το Let's Encrypt να αποτυγχάνουν σποραδικά.
kaiki.testing.gr · TXT (SPF) v=spf1 ip4:IP_SERVER ~all — ή ό,τι σας πει η Cretaforce αν στέλνετε μέσω relay (include:…). Μία μόνο εγγραφή SPF ανά όνομα.
ΕΠΙΛΟΓΕΑΣ._domainkey.kaiki.testing.gr · TXT (DKIM) Το δημόσιο κλειδί που δίνει ο mail server. Ο επιλογέας (selector) είναι δικός του.
_dmarc.kaiki.testing.gr · TXT v=DMARC1; p=none; rua=mailto:ΕΣΕΙΣ@ΤΟ-DOMAIN-ΣΑΣ — p=none στο staging, για να βλέπετε αναφορές χωρίς να χάνεται email.
Το domain αποστολής

Τα SPF/DKIM/DMARC πάνε στο domain της διεύθυνσης MAIL_FROM_ADDRESS. Αν στείλετε από noreply@testing.gr αντί για @kaiki.testing.gr, οι εγγραφές μπαίνουν στο testing.gr — και προσοχή να μη σβήσετε το SPF που ίσως έχει ήδη.
